## 1. Purpose and explicit product decisions

For derived **Best School / Academy / Club / City / State / Institution** prizes from an **individual** tournament, score the selected K eligible individual players and break team-level ties transparently. Do **not** apply team-vs-team match-point rules: this product does not automatically contain team match results.

**Locked new-team default** (event-specific published regulations take precedence):

1. `TOTAL_POINTS_DESC` — sum **genuine, finite, verified** points of the K counted players; higher wins; **fixed primary** in this scope. Preserve the existing rank-first player selection and explicit gender minima; selection changes are **out of scope**.
2. `SCORE_VECTOR_DESC` — sort the same K selected players' individual points descending and compare lexicographically (highest scorer, second, …, Kth). This is a custom **team award rule**; not a universal FIDE/AICF tie-break.
3. `SOURCE_TB(1)`, `SOURCE_TB(2)`, … `SOURCE_TB(n)` — all TB columns *actually present* in the successfully imported Swiss-Manager XLS/XLSX, in source order, provided their precise meaning, operation, direction and source are **validated**. All are eligible to appear in the organizer's ordered sequence; an unsuitable/undefined one may be visible but not used to decide money automatically. Do not hardcode Buchholz Cut-1 or Sonneborn-Berger as TB1/TB2.
4. On unresolved equalities after all applicable declared methods: `TIE — RESOLUTION REQUIRED`, no automatic monetary winner; organizer/arbiter records a permitted adjudication method. **Play-off is proposed only if the tournament's published regulations provide the necessary conditions, format and procedure**; FIDE C.07 Article 4.2 can require lots when a list is exhausted unless event regulations permit an unbroken tie. The app **never** draws lots, announces a playoff, or allocates by alphabet without authority.

**Remove Rank Sum completely from NEW active team ranking, rule controls, active Team organizer/public tables, A4 print, server Team PDF (if applicable), and Team worksheet of Final Prize XLSX** when the scored output change is authorized. Preserve legacy `rank_sum` / historical player snapshots/versions for interpretation and recovery; do not destructively delete old DB columns, mutate published awards or rewrite old rankings. Do not use `best_individual_rank` or institution-name sorting to confer prize entitlement.

## 2. Tournament-rule authority and editable scope

- The organizer defines a **per-prize-group** ordered list in the existing **Team Prizes → Edit Rules** drawer. Default = fixed points, score vector, validated TB1…TBn. Organizer may reorder criteria **after** fixed total points, including score vector relative to imported TBs, using accessible drag handles **and keyboard Move Up / Move Down**. Do not create new routes, a separate settings page, or duplicate actions. Rework/remove the existing disabled single-option **Scoring Mode** selector instead of creating a second competing control. Show a compact read-only rule summary on each group card.
- Do not allow total points to be dragged, removed, replaced or changed to an alternate primary scoring method in this scope. Do not let the organizer reorder **individual standings**; team ranking is separate.
- Organizer must attest that the ordered list matches the event's **published team-prize regulations**, with a brief publication/reference note or explicit event-rule identifier. If supplied regulations differ, **do not silently override them** with app defaults. For events with no authorized ranking criteria, do not treat a custom platform default as automatically pre-published; require documented authorized review before awards impacted by tie-breaks are finalized.
- Changes remain draft and previewable prior to team finalization. After versioned results exist, rule edits or player re-imports must invalidate/recompute a **new reviewed version** with previous version/published pin unchanged. Prevent concurrent/stale revisions. Do not mutate prior published `team_allocations` or its `allocation_version`.
- Preserve existing size and gender-minimum semantics. The current selector sorts players by individual rank then id, selects K within the configured female/other minima. Because team size K is identical within one group, `sum(points)` and `average(points)` order identically, but do not introduce average without published-rule approval.

## 3. Import contract: variable TB1 … TBn

**Source reality (main):** `src/utils/headerAliases.ts`, `src/utils/importPresets.ts`, `src/components/ColumnMappingDialog.tsx`, `src/pages/PlayerImport.tsx` and `src/utils/playerImportPayload.ts` currently map standard fields including `points`, but **do not** map/persist TB1…TBn as typed team-scoring data. The generated `players` type has no TB columns. A current Excel export might have zero, one or many TBs; the claim that *all* imported files contain them was not proven with an accessible workbook corpus. Swiss-Manager explicitly documents extra TB columns needing user-selected export visibility. Imported file has not been verified as a final, complete results file unless a real validation proves it.

**Required ingestion behavior (implementation proposal; physical storage not yet authorized):**
- Detect ordered TB headers with a precise anchored rule for `TB1`, `TB2`, … `TBn` and recognized unambiguous variants. Keep source ordinal, exact original heading, source worksheet/column reference, import batch identifier/hash, and raw value-to-player association. Do not accidentally read `TB10` as `TB1`, nor confuse duplicate renamed columns, ordinal gaps, empty headers or comment/summary rows.
- Offer a compact post-import **“Tie-break columns detected”** summary in the existing mapping/import review surface: e.g. `TB1 · 172/172 values · method not identified`; `TB2 · 171/172 · 1 missing`. Explain how these **individual** values may later appear as **team** tie-breaks. Missing columns are listed as **not exported** rather than fabricated. Reuse existing mapping dialog; no new route.
- `TB1` means **first source tie-break**, not “Buchholz” by definition. To activate a TB in automatic awards, record the **true named metric**, its published-rule reference, compatible operation on K selected individual values, sort direction and any method-specific unplayed-round/precision restrictions. Values with unknown identity are `needs_definition`, not usable as money-deciding numbers. A label like `TB1 (Buchholz Cut-1)` is legitimate only when established from the source event's settings/regulations.
- Parse numeric fields with explicit precision and valid zero; treat missing/blank/malformed/not-final/ambiguous as **missing or invalid**, not zero. Preserve raw numeric text for audit without exposing personal source files or PII in logs. Reject ambiguous mappings and nonfinite numbers. Store compact per-tournament TB descriptor(s) and per-player values in **typed, server-validated, authorized** structures with stable ordinal/metric identification and import-version provenance. Choose the smallest safe additive schema/storage change **only after** live dependency/rollback review; do not assume arbitrary `tags_json` can safely store scoring data.
- Multiple imported batches and replacement imports must pin the tournament's currently selected validated batch and make stale TB definitions/inconsistent column sets unusable for active awards until remapped/reconfirmed. Never infer missing per-player values from a different file or imported rank.
- The full imported TB sequence should be available for configuration, but a method unsupported for deriving a **team** comparison is rendered `Needs definition / cannot auto-rank` with explanation; it may be recorded as declared but must not silently be skipped if reached in an unresolved cash-prize tie.

## 4. Team comparison methods and correctness

- **Fixed first stage:** `sum(K selected.points)` descending; no partial-zero fallback. Selected players and slot eligibility must be validated first. If any selected player lacks finite points, mark affected team group **DATA INCOMPLETE**, block new automatic prize finalization/export of misleading team winners. Do not suppress unrelated individual prize exports; team worksheet must fail closed where configured Team results are missing/invalid.
- **Second and reorderable stage:** sorted score vector, lexicographic **descending**; compare each position once and only split still-tied subgroups. Example A (7,5), ranks (1,5), B (6,6), ranks (2,3): both 12; default vector awards A at first position (7 > 6). That is valid *only under the published event's team award rule*.
- **TB stage:** for a **verified numeric, additive, higher-wins method**, aggregate the SAME selected K players' source TB values using an explicitly recorded `sum` policy (e.g. sum of individual Buchholz values when this team-level adaptation is in the published rules). For lower-is-better or method-specific comparisons, use only the **explicitly documented compatible comparator**. Never infer that `TB2` is a higher-wins scalar. Direct encounter and other conditional/non-additive methods are **not** convertible to `sum(TB)` by default. Unsupported metadata/operation => `NEEDS_DEFINITION`; block a still-needed prize decision, do not substitute another rule or silently drop this step.
- **Use methods lazily only for surviving tie subsets**. A later TB missing for one selected player does **not** retroactively invalidate a result fully decided earlier. For a tie that reaches it, require complete, comparable, same-definition data for all participating teams. Mark unresolved **award boundaries**, including different-valued 1st/2nd/3rd prize places and winner-versus-runner-up, not merely the last money/no-money boundary.
- Stable display sorting for unresolved tied rows is allowed, **but is not a rank assignment** or evidence of winner ordering. Use a tied position/status rather than fictional distinct cash ranks.
- Manual adjudication is restricted to genuinely unresolved ties, with server-authoritative organizer/master permissions and an arbiter/authorized-ruling record: criterion/explanation, cited regulation, affected teams/prizes, version and actor/time. Enforce the authority and audit semantics server-side, not via button visibility alone. The existing `resolve_team_tie` RPC/TeamTieBreakDialog is a review target; a free-text note must not become a loophole for arbitrary payout.

## 7. Acceptance cases (synthetic only; minimum implementation test matrix)

1. A=(7,5) and B=(6,6), both 12: default vector ranks **A over B** if event rule is authorized; rearranging TB1 before vector changes comparator **only** if TB1 is verified and authoritative.
2. Same points + same vector, TB1 equal, TB2 different: TB2 determines outcome; 3+ tied teams partition correctly at each stage without dropping a club/runner-up.
3. A file with TB1…TB12 preserves numeric ordinal order; TB10 is not TB1. Zero-TB export yields no fabricated rules; missing columns reported accurately.
4. TB1 means an event-specific named source method; mismatched or unknown labels, non-additive direct encounter, wrong direction, duplicate headers, blank/NaN cells, different import batches => correct **needs-definition/missing-data** behavior. An unneeded later TB does not block a result settled earlier.
5. Missing selected **points**, insufficient K, invalid gender slot selection, partial TB coverage, tied 1st/2nd different cash and winner/runner-up boundaries trigger precisely scoped blocking/diagnostic states; never backfill zero.
6. Rule move/keyboard interactions update only **draft group rules**, never individual ranking or primary points; stale revisions, changed source file and attempted post-publication override are prevented.
7. New team scorer/preview, finalize-compatible read, backfill, server/public pinned versions, Team print/PDF, fourth XLSX, and tie resolution agree at same exact commit/ref with correctly recorded criterion/method.
8. Non-owner and non-master cannot configure/adjudicate or access unpublished TB metadata; public results contain only published data and no ineligible institution diagnostics. Legacy published snapshots remain identical and explainable. No CSV support.
